## 1. 产品概述

### 1.1 产品背景

随着个人线上账户数量爆炸式增长（社交、银行、购物、办公、订阅服务等），普通用户平均需要管理 80–100 个账号密码。由此产生三类典型问题：

1. **记不住**：为减轻记忆负担，用户倾向于使用弱密码或在多个平台重复使用同一密码。
2. **不安全**：明文记在备忘录、Excel、聊天记录中，一旦设备丢失或被截图，密码全部泄露。
3. **管理乱**：账号分散、找不到、忘记是哪个邮箱注册的，找回成本高。

行业数据表明，超过 60% 的数据泄露事件与弱密码或密码复用直接相关。市面上已有 1Password、Bitwarden、Keychain 等成熟产品，但普遍存在 **学习成本高、强依赖云端、订阅费贵、界面复杂** 等问题，对国内轻量级用户不够友好。

### 1.2 产品定位

> 一款 **本地优先、生物识别保护、零学习成本** 的轻量级个人密码管理工具。

核心理念：**密码永远以加密形态存在，只有"你本人"（指纹/面容）才能解开。**

- 一句话定位：**指纹一按，密码到手。**
- 产品类型：移动端工具类 App（iOS / Android）。
- 商业模式：基础功能免费，进阶功能（云备份、跨设备同步、高级健康报告）订阅制（v2.0+ 规划）。

### 1.3 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 普通大众用户 | 账号多、记性差、安全意识中等 | 安全存放、快速取用 |
| 安全敏感用户 | 关注隐私、不信任云端 | 本地加密、数据不上传 |
| 老年/数字弱势用户 | 操作简单需求强 | 大字体、一键复制、流程简单 |

### 1.4 用户痛点与产品价值

| 用户痛点 | 产品解决方案 | 用户价值 |
| --- | --- | --- |
| 密码明文记录易泄露 | 默认加密显示 + 生物识别解锁 | 安全感 |
| 弱密码 / 重复密码 | 密码健康度检测 + 强密码生成器 | 安全升级 |
| 找不到账号 | 分类 + 搜索 | 高效 |
| 手动输入密码繁琐易错 | 一键复制账号/密码 | 省心 |
| 担心数据上云被窃取 | 本地加密存储，默认不联网 | 隐私可控 |

- **业务目标**：上线 6 个月内累计下载量 50 万，月活 10 万。

## 3. 用户画像与典型场景

### 3.1 用户画像（示例）

**小林，28 岁，互联网公司白领**
- 手机里有几十个 App，密码经常忘记，每次都点"忘记密码"重设。
- 怕麻烦，常年用一个密码走天下，知道不安全但懒得改。
- 期望：有个地方能安全存密码，用的时候一键拿出来。

### 3.2 典型使用场景

1. **存密码**：注册新网站时，用 App 生成强密码并保存。
2. **取密码**：登录某网站时，打开 App，指纹解锁，搜索并一键复制密码。
3. **查健康**：定期查看哪些密码太弱或重复，按提示逐个修改。
4. **找账号**：忘记某平台用哪个邮箱注册，通过分类/搜索快速定位。

#### 5.1.5 账户恢复机制（P0）

主密码是加密密钥的派生源，本身**不被明文存储**。为兼顾"安全"与"可恢复"，v1.0 采用 **恢复码为主、安全问题为辅** 的双重恢复方案。

**技术原理（密钥包裹 / Key Wrapping）：**
- 真正加密数据的是随机生成的数据加密密钥 **DEK**；
- DEK 被两份独立包裹后存储：① 用主密码派生的密钥加密；② 用**恢复码**派生的密钥加密；
- 正常解锁：经生物识别授权后用主密码解出 DEK；忘记主密码时：用恢复码解出 DEK，再引导用户重设主密码并重新包裹；
- 因恢复码与主密码相互独立，二者任一可用即可恢复全部数据。

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| REC-01 | 初始化时自动生成一组高熵**恢复码**：**25 位 Crockford Base32 字符（约 125bit 熵）+ 1 位校验位**，按 `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` 分 5 组展示，引导用户抄写/保存到安全位置（格式规范见 §5.1.6） | P0 |
| REC-02 | 要求用户**确认已保存**恢复码（如二次回填校验）后方可继续 | P0 |
| REC-03 | 从**内置题库**中选择 3 个不同安全问题（支持 1 个自定义），作为辅助身份验证；答案经规范化后哈希加盐本地存储（题库与规则见 §5.1.6） | P1 |
| REC-04 | "忘记主密码"入口：校验恢复码 → 用恢复码解出 DEK → 强制重设主密码 → 重新包裹 DEK | P0 |
| REC-05 | 安全问题仅用于辅助身份核验（如恢复流程二次确认、高风险操作），**不单独作为解密钥匙**（熵低，安全性不足） | P1 |
| REC-06 | 支持在设置页**重新生成恢复码**（旧码立即失效并重新包裹 DEK） | P1 |
| REC-07 | 明确告知：**主密码与恢复码若同时丢失，数据将无法恢复**（安全设计的必要取舍） | P0 |

#### 5.1.6 恢复码与安全问题实现规范

**恢复码格式**
- **熵与编码**：125bit 随机数，采用 **Crockford Base32** 字符集（`0-9 A-Z`，剔除易混淆的 `I L O U`），得 25 位字符，末尾追加 1 位校验位用于输入纠错。
- **展示**：`XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` 五组分隔、全大写；生成时全屏一次性展示，支持「复制 / 保存为图片」。
- **确认**：保存后要求用户**随机回填其中 1–2 组**完成校验，确认确已保存。
- **输入容错**：校验时自动忽略连字符/空格、大小写归一、`I→1`/`O→0` 等等价纠正；校验位不通过即时提示。
- **再生成**：仅可在设置页「恢复码管理」中重新生成，旧码立即失效并重新包裹 DEK。
- *（v1.1 可选）* 提供 12 词助记词展示模式，便于不便抄写字符码的用户。

**安全问题规则**
- 必须选择 **3 个不同问题**，至少 2 个来自内置题库，最多 1 个自定义问题。
- **答案规范化**：去除首尾空格、合并连续空格、转小写、全角转半角后再做 **加盐哈希**（Argon2id / SHA-256+salt）本地存储；原文不留存。
- 单个答案长度 ≥ 2 个字符；找回流程中需**全部答对**方可通过（仅作辅助核验，不单独解密 DEK）。
- 内置题库见附录 §11.3。

### 5.5 密码健康度（P1）

帮助用户主动发现并改善安全隐患，是产品差异化亮点。

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| HLT-01 | 计算并展示整体"健康分"（0–100），含可视化仪表盘 | P1 |
| HLT-02 | **强弱检测**：基于长度、字符多样性、是否常见弱口令，将密码标记为强/中/弱 | P1 |
| HLT-03 | **重复检测**：识别在多个条目中使用了相同密码，标记并列出 | P1 |
| HLT-04 | **旧密码提醒**：标记超过 180 天未更新的密码（P2） | P2 |
| HLT-05 | 列出问题清单（弱/重复/旧），每项提供"立即修改"快捷入口 | P1 |
| HLT-06 | 健康检测全部在**本地完成**，不上传任何密码数据 | P0 |

**健康分计算规则：**

基础分 100，按下表权重对每个条目累计扣分，最终分 = max(0, 100 − 总扣分)：

| 问题类型 | 判定标准 | 扣分 |
| --- | --- | --- |
| 弱密码 | 长度 < 8，或仅含单一字符类型，或命中常见弱口令库 | 每条 −15 |
| 中强度密码 | 长度 8–11 且字符类型 ≤ 2，未达"强"标准 | 每条 −5 |
| 重复密码 | 同一密码被 N（≥2）个条目使用 | 该组每个条目各 −10 |
| 旧密码（v1.1+） | 超过 180 天未更新 | 每条 −3 |

> 说明：同一条目存在多类问题时**扣分可叠加**（如"又弱又重复"），总分下限为 0。
>
> **分档**：90–100 优秀（绿）、60–89 良好（黄）、0–59 需改善（红）。

### 5.6 数据备份与导入（P0）

为应对卸载、换机导致的本地数据丢失，v1.0 提供**本地加密导出/导入**作为基础备份手段（加密云备份在 v2.0）。

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| BAK-01 | 支持将全部密码库**加密导出**为单个备份文件（如 .spaenc），导出前需生物识别/主密码验证 | P0 |
| BAK-02 | 导出文件使用**独立备份密码**加密（AES-256，密钥经 KDF 派生），与主密码解耦 | P0 |

| BAK-04 | 支持从备份文件**导入恢复**：输入备份密码 → 解密 → 校验完整性 → 入库 | P0 |
| BAK-05 | 导入时提供**冲突处理**策略（跳过 / 覆盖 / 同时保留） | P1 |
| BAK-06 | 备份文件不含明文密码，全程本地处理，不经过任何服务器 | P0 |

#### 5.6.1 .spaenc 备份文件格式与版本兼容

**文件结构（明文头 + 加密体）：**

| 区段 | 内容 | 说明 |
| --- | --- | --- |
| Magic | `SPAENC`（6 字节） | 文件标识，导入前先校验 |
| format_version | uint16（当前 = 1） | 文件结构版本 |
| KDF 参数 | 算法标识 + 迭代/内存参数 + salt(16B) | 由备份密码派生密钥 |
| Cipher 参数 | 算法标识（AES-256-GCM）+ nonce(12B) | 加密参数 |
| Ciphertext | 加密后的密码库数据（JSON） | 全部条目密文 |
| Auth Tag | GCM 认证标签 / HMAC | 完整性与防篡改校验 |

**版本兼容策略：**
- **导入校验顺序**：先验 Magic 与 `format_version` → 再验 Auth Tag 完整性 → 最后解密，任一环节失败即中止并提示。
- **向后兼容**：高版本 App 可导入低版本备份，内置逐版本迁移器将旧结构升级到当前版本。
- **前向保护**：低版本 App 遇到更高的 `format_version` 时，明确提示「请升级 App 后再导入」并**拒绝解析**，避免数据损坏。
- **版本递增规则**：仅当文件结构发生破坏性变更时 `format_version +1`；App 永久保留对历史版本的读取能力。

### 6.1 页面结构

```
        │

             ├─ 分类管理页
             ├─ 健康度页（健康分 + 问题清单）
             └─ 设置页（自动锁定、主密码修改、恢复码管理、加密导出/导入、关于）
```

### 6.2 核心流程图

**流程一：取用密码（核心高频）**
```
打开 App → 生物识别解锁 → 搜索/浏览 → 点击条目 →
点击"复制密码" → Toast 提示 → 粘贴登录 →（60s 后剪贴板自动清空）
```

**流程二：新增密码**
```
主页"+" → 输入名称/账号 → 点击"生成密码"（或手动输入）→
选择分类 → 保存 → 列表更新
```

**流程四：主密码恢复（忘记主密码）**
```
解锁页"忘记主密码？" → 输入恢复码（必要时答安全问题）→
校验通过 → 用恢复码解出数据密钥 → 强制设置新主密码 →
```


**流程三：改善健康度**
```
进入健康页 → 查看健康分 → 查看问题清单 → 点击某弱/重复项"立即修改" →

```

## 7. 非功能需求

### 7.1 安全性（最高优先级）

| 编号 | 要求 |
| --- | --- |
| NF-SEC-01 | 所有密码数据使用 AES-256 等强加密算法本地加密存储 |
| NF-SEC-02 | 加密密钥由主密码经 KDF（Argon2id / PBKDF2，足够迭代次数）派生，密钥不落地明文 |
| NF-SEC-03 | 生物识别仅作为本地解锁手段，密钥可借助系统安全硬件（Secure Enclave / Keystore）保护 |
| NF-SEC-04 | App 默认不联网、不上传任何密码数据（隐私优先） |
| NF-SEC-05 | 内存中明文密码使用后及时清理，避免内存泄露 |
| NF-SEC-06 | 数据导出文件需加密（带独立备份密码的加密包），导入需校验完整性与密码 |
| NF-SEC-07 | **核心加密模块开源**（加密、KDF、恢复码/密钥包裹逻辑），接受社区审计以建立信任；UI 与业务层可闭源 |
| NF-SEC-08 | 恢复码具备足够熵（建议 ≥128bit），仅在本地校验，不上传 |

### 7.2 性能

| 要求 | 指标 |
| --- | --- |
| 冷启动到解锁页 | ≤ 1.5 秒 |
| 解锁后列表加载（1000 条内） | ≤ 1 秒 |
| 搜索响应 | ≤ 300 毫秒 |

### 7.3 兼容性

- iOS 14+，Android 9+。
- 适配主流机型与屏幕尺寸，支持深色模式。
- 支持大字体/无障碍模式（照顾数字弱势群体）。

### 7.4 可用性

- 核心操作零学习成本，新用户首次使用有简洁引导。
- 关键操作（删除）二次确认，防误操作。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 用户忘记主密码导致数据无法找回 | 高 | v1.0 提供**恢复码 + 安全问题**恢复机制；设置时强引导离线保存恢复码 |
| 用户同时丢失主密码与恢复码 | 高 | 设置流程强制确认已保存恢复码；提供加密备份导出；明确告知二者皆失则数据不可恢复（安全取舍） |
| 生物识别在部分设备不可用 | 中 | 主密码兜底，保证可用性 |
| 本地数据随卸载/换机丢失 | 高 | v1.0 提供**本地加密导出/导入**作为基础备份；v2.0 提供加密云备份与同步 |
| 安全信任建立难 | 高 | 透明说明加密原理、强调"不上云"；**v1.0 即开源核心加密模块**接受社区审计 |
| 剪贴板被其他 App 读取 | 中 | 复制后限时自动清空，并提示风险 |
